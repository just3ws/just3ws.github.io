# Creator launch workbench

Prepared November 5, 2026. Promotion copy below is an AI-assisted draft for
Mike's review. None of these messages has been sent or scheduled.

## The offer

Free following plus one paid membership: Studio Notes at $5/month. Occasional
notes about making videos, preserving interviews, and building software. No
fixed publishing schedule. Public work stays public. Membership includes no
private recordings, consulting, or promised individual access.

The live Patreon state must be verified before the site changes from draft to
published. The canonical snapshot was last checked November 4, 2026.

For paid engineering work, use the existing engagement route. Start with one
agreed workflow, a map, evidence and unknowns, and proposed next steps. Agree
access, scope, timing, and fee before work begins.

## Launch sequence

1. Review the sample note at `/support/#studio-note`, the workflow inquiry at
   `/engagements/#workflow-investigation`, and the three drafts below.
2. Resolve the historical corrections and review the promoted photo selections.
   Keep dates tied to their sources and image descriptions honest.
3. Review the accumulated commits before publishing the branch. Build production
   output and run required release gates; do not deploy the development build.
4. In the Patreon dashboard, read back the About text, free-follow option, $5
   Studio Notes tier, cover, avatar, and welcome post. Keep old bootstrap tiers
   unpublished. Check required account and payout setup in Patreon without
   copying private financial details into this repository.
5. Publish the reviewed page and welcome post when the release is ready. User
   authorization in this session covers the agreed launch; verify the result
   rather than treating a saved draft or API snapshot as proof.
6. Check the page while logged out: free following is understandable, the paid
   tier has the intended price, and checkout begins correctly. A paid purchase
   is not needed for a browsing check.
7. Update campaign `page_status` to `published`, reconcile the observed and
   desired statuses, and record the actual verification date. Rebuild the site.
8. Verify public support, timeline, engagement, and contact routes; then publish
   the first reviewed announcement. Check canonical/social previews and mobile
   browsing before broad promotion.

Do not turn blocked network, browser, or account access into a claimed launch.
Do not send private outreach or contact historical interviewees automatically.

## Measurement

Existing GoatCounter tracks page views and outbound links. After launch,
confirm the real Patreon clicks appear; do not assume loaded code proves event
delivery. Record free and paid memberships separately using Patreon aggregates.
Never put member names or financial account details in public data.

Review support-page visits, outbound Patreon clicks, free joins, paid joins,
and relevant engineering inquiries. These are separate stages, not a claim of
person-level attribution. Add dedicated tracking only if these reports cannot
answer the actual launch questions.
