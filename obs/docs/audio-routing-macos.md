# macOS Audio Routing & Multi-Track Engineering Guide

This guide establishes the audio pipeline for the UGtastic rewatch series on macOS Golden Gate (Darwin 27) with Apple Silicon.

---

## 1. Native Sound Capture in macOS Golden Gate

macOS Golden Gate features first-class native audio capture capabilities built into the operating system through CoreAudio and ScreenCaptureKit. Legacy third-party kernel extensions and virtual loopback audio drivers (such as Soundflower, BlackHole, or Loopback) are completely obsolete.

OBS Studio on macOS Golden Gate natively provides two distinct capture methods:

### Method A: Per-Application Audio Capture (`sck_audio_capture`)
- Directly taps the PCM audio stream of a specific running application (such as the Chromium browser).
- Complete isolation: only audio generated by the Chromium interview player enters this channel.
- Automatically excludes all other apps: Slack pings, Mail chimes, Spotify, and terminal bells never leak into the stream.
- Exclusion filter (`setExcludesCurrentProcessAudio: true`): Golden Gate automatically prevents OBS monitoring output from echoing back into the capture buffer.

### Method B: System Desktop Audio Capture (`coreaudio_output_capture`)
- Taps default CoreAudio system output directly without external loopback cables.
- Select it with `DesktopAudioDevice1=default` in the OBS profile when a session intentionally needs system output.
- Optional for sessions that intentionally include system output. The base rewatch scene collection disables it because Chromium is already captured by ScreenCaptureKit; enabling both can double the interview audio and include notification sounds in the program mix.

Both methods operate with hardware-locked 48,000 Hz sample rate synchronization, eliminating audio drift, sample rate mismatch crackling, and buffer underruns.

## 2. Preventing Feedback Loops

When hosting a reaction video or commentary stream:

1. **Always Wear Headphones or In-Ear Monitors (IEMs)**:
   If video sound plays out of your physical laptop speakers into your open microphone, your stream will suffer from hollow room echo and comb filtering.
2. **Headphone Monitoring**:
   Listen to the video playback normally through your headphones. ScreenCaptureKit captures the browser audio digitally inside macOS and sends it straight to OBS.
3. **Mute on Pause**:
   Because you control video playback with the spacebar in Chromium, pausing the video instantly silences the application audio, leaving your vocal channel clear for commentary.

## 3. Host Vocal Processing Chain

The default scene collection applies a studio-grade filter chain to `Mic/Aux` to ensure broadcast-quality voice reproduction:

### Filter 1: Noise Suppression (RNNoise)
- **Algorithm**: RNNoise (Neural network based noise suppression)
- **Purpose**: Eliminates room fan noise, mechanical keyboard clicks, and subtle room reverberation without cutting off the beginnings or ends of words.

### Filter 2: Vocal Compressor
- **Ratio**: 4.0:1
- **Threshold**: -18.0 dB
- **Attack Time**: 6 ms
- **Release Time**: 60 ms
- **Output Gain**: +3.0 dB
- **Purpose**: Smooths out natural volume changes between quiet reflections and energetic commentary, keeping vocal presence consistent.

### Filter 3: Safety Limiter
- **Threshold**: -1.5 dB
- **Release Time**: 60 ms
- **Purpose**: A strict digital brickwall that prevents clipping or harsh digital distortion if you laugh or speak loudly.

## 4. Multi-Track Master Recording Architecture

The OBS Profile (`The Sound Above`) is configured with **Advanced Multi-Track Recording** (`RecTracks=15`, capturing 4 independent audio tracks simultaneously). Automatic duration and size splitting are disabled so a session stays one edit-ready hybrid MOV. All four recording tracks use 320 kbps AAC, including the program mix:

```
+-------------------------------------------------------------------------+
|                  4-TRACK MASTER RECORDING ARCHITECTURE                  |
+---------+------------------------------+----------+---------------------+
| Track # | Name & Content               | Bitrate  | Intended Destination|
+---------+------------------------------+----------+---------------------+
| Track 1 | Program Mix                  | 160 kbps | Recording / Preview |
|         | (Host Mic + Chromium)        |          |                     |
+---------+------------------------------+----------+---------------------+
| Track 2 | Host Vocal Solo              | 320 kbps | Studio Shorts Prep, |
|         | (Clean Microphone Only)      | AAC      | Whisper Transcripts |
+---------+------------------------------+----------+---------------------+
| Track 3 | Browser Video Audio Solo     | 320 kbps | Original Interview  |
|         | (Chromium Playback Only)     | AAC      | Reference Track     |
+---------+------------------------------+----------+---------------------+
| Track 4 | Reserved, currently unassigned | 320 kbps | Configure per dialogue session |
|         | No guest application source is included in the base profile. | AAC | Do not assume guest isolation |
+---------+------------------------------+----------+---------------------+
```

### Why This Saves Hours in Post-Production

The recorded `.mov` file selects four tracks. The base rewatch setup populates Tracks 1-3; Track 4 remains silent until a guest app is explicitly configured:
1. **Podcast Release**: Import Track 2 directly into an audio editor to master an isolated audio podcast episode without the video noise.
2. **YouTube Shorts Extraction**: Cut vertical reaction clips using the Editorial Content Studio (`/studio/`) without having your voice permanently baked into the interview audio at an uneditable volume.
3. **Automated Retranscription**: Feed Track 2 directly into local Whisper (`whisper-ctl`) to produce clean transcripts of your own commentary.
